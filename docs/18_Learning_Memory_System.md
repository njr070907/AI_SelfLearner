# Learning Memory System

## 1. 目的

记忆系统使 AI 能在不假装“永久了解用户”的情况下，利用相关历史提供更好的学习判断。记忆必须可追溯、可过期、可纠正、可删除。

## 2. 四层记忆

### 2.1 Working Memory

当前会话中的概念、问题、回答、追问和临时状态。会话结束后写入学习事件，不直接成为长期画像。

### 2.2 Episodic Learning Memory

每次学习的不可变事件：时间、概念、问题、原始回答、诊断、用户反馈与版本。它是后续重算的事实基础。

### 2.3 Semantic Knowledge Memory

用户对各概念的知识状态、误区、依赖和掌握轨迹。它是派生数据，可从事件重算。

### 2.4 Cognitive Memory

跨会话候选模式、有效学习方式、长期目标变化。进入门槛最高，必须有多源证据与用户可见性。

## 3. 写入规则

| 内容 | 是否自动写入 | 条件 |
|---|---|---|
| 用户原始回答 | 是 | 用户提交 |
| 单次诊断 | 是 | Schema 校验成功 |
| 知识状态 | 是 | 按版本化算法派生 |
| 误区 | 条件写入 | 用户明确表达错误命题 |
| 认知模式 | 否/候选 | 多条独立证据 |
| 敏感人格结论 | 禁止 | 不属于产品范围 |

## 5. 检索规则

模型调用只检索与当前任务相关的少量记忆：

1. 同一概念近期记录；
2. 直接前置概念状态；
3. 与当前错误类型相关的高质量模式；
4. 用户明确纠正过的相关结论。

使用结构化过滤优先于纯相似度。检索结果包含来源与置信度，不能只给模型一个没有证据的摘要。

## 6. 遗忘与过期

- 事件不自动过期，但用户可删除；
- 当前知识状态随时间标记“需复测”；
- 候选模式长期无新证据时降低新近性；
- 用户目标失效后归档，不继续影响推荐；
- 派生摘要有算法版本，可随重算替换。

## 7. 冲突处理

当新记录与记忆冲突：

- 同时保存支持与反证；
- 降低或重新计算置信度；
- 检查任务难度、领域和时间差异；
- 不简单用“最新一条覆盖旧结论”；
- 必要时向用户呈现：“在不同任务中表现不一致”。

## 8. 用户界面

“AI 记住了什么”页面分为：

- 学习历史事实；
- 当前知识状态；
- 候选观察；
- 用户确认的偏好/目标。

每项提供来源、修改/反馈、隐藏和删除。用户应能清空全部记忆并了解影响。

## 9. 隐私

- 默认只存完成功能所需数据；
- 敏感文本不进入普通日志；
- 外部模型调用只传当前必要片段；
- 跨用户绝不共享原始记忆；
- 删除用户时清理事件、派生状态、向量与缓存；
- 备份中的删除策略必须明确。

## 10. MVP

第一版只实现会话事件、同概念历史和知识状态。不要创建“永久人格记忆”。只有 30 天真实实验证明价值后，再引入候选模式和用户管理界面。
