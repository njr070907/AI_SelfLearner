# 隐私、安全与数据治理

> 本文是工程要求，不替代目标市场的法律意见。公开测试前应根据运营地区完成适用法规审查。

## 1. 数据原则

- 目的限制：只收集完成学习诊断所需数据。
- 最少收集：默认不要求真实姓名、电话、精确位置或生日。
- 用户控制：可查看、纠正、导出、删除自己的数据。
- 透明：明确哪些内容会发给外部模型、保存多久、用于什么。
- 可撤回：退出研究或模型改进不影响基本产品使用。

## 2. 数据分类

| 等级 | 示例 | 要求 |
|---|---|---|
| Public | README、公开文档 | 可公开 |
| Internal | 指标定义、非敏感配置 | 限团队 |
| Confidential | 学习回答、诊断、画像、反馈 | 加密、最小权限、禁正文日志 |
| Restricted | API 密钥、认证凭据、删除凭证 | 密钥系统、严禁进入数据库正文/日志 |

用户可能主动输入健康、身份、工作或其他敏感信息，系统应提示避免输入，并将所有自由文本按 Confidential 处理。

## 3. 数据清单与目的

- 会话与回答：提供诊断和历史。
- 诊断与反馈：展示结果、纠错、质量评估。
- 模型/Prompt/Schema 版本：可追溯与回滚。
- 运行元数据：可靠性、成本和安全；默认不含正文。
- 研究数据：单独明确同意，不与基础服务捆绑。

禁止把用户内容用于训练或共享给第三方，除非另行清晰告知并获得主动同意。

## 4. 权利流程

- 访问/导出：提供机器可读 JSON，包含数据字典和版本。
- 纠正：用户可否定诊断；后续聚合不得继续当作确认事实。
- 删除：删除主数据、派生画像和可定位缓存；备份按周期过期，不再恢复到线上使用。
- 撤回同意：停止对应的未来处理，不影响撤回前合法处理记录。

每次请求生成审计 ID；身份验证强度应与数据敏感度匹配。

## 5. 安全控制

- 传输 TLS，静态数据与备份加密。
- 最小权限服务账号，生产与开发凭据分离，定期轮换。
- 输入长度限制、输出编码、依赖扫描、密钥扫描。
- Prompt 注入按不可信输入处理；用户内容不能改变系统规则或调用未授权工具。
- 外部模型请求设置超时、数据最小化和供应商数据保留选项。
- 管理操作与数据导出/删除写审计事件，但审计日志不保存正文。

## 6. 威胁清单

重点防范：越权读取他人历史、日志泄露回答、Prompt 注入泄露系统内容、重复请求破坏数据、恶意大输入导致成本耗尽、依赖/密钥泄露、备份未加密、删除不完整、模型输出被当作可执行代码。

任何富文本、Markdown 或代码展示都必须转义；模型输出不得直接执行 SQL、Shell、Python 或浏览器操作。

## 7. 保留基线

- 运行日志：30 天。
- 安全审计：180 天或按适用要求。
- 学习内容：用户账户存续期间，或用户选择的更短期限。
- 已删除数据：在线系统尽快删除；备份在最长 35 天内自然淘汰。
- 未完成匿名会话：30 天后删除。

实际值必须通过配置和定期清理任务落实，并在隐私说明中保持一致。

## 8. 上线隐私门槛

公开测试前必须存在：隐私说明、供应商清单、数据流核对、删除/导出端到端测试、泄露响应联系人、未成年人策略和同意记录。若未完成，只允许单人本地实验。
