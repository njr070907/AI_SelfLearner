# AI Growth Companion MVP 功能 PRD

## 1. 文档目标

定义可在 30 天内完成并真实使用的 Feynman Intelligence Engine v0.1。MVP 只验证核心假设，不承担完整产品愿景。

## 2. 核心假设

> 如果 AI 持续分析用户对知识的解释，它能否比普通问答工具更准确地发现知识漏洞，并帮助用户选择下一步学习行动？

## 3. 目标用户

### 主要用户

- 正在学习数学、编程、AI、经济学等复杂概念的大学生与自学者；
- 已有明确知识点，愿意用自己的话解释；
- 希望得到诊断，而不只是标准答案。

### 非目标用户

- 只想快速获得作业答案的人；
- 需要正式考试判分或资格认证的人；
- 需要心理、医疗或职业定论的人。

## 4. 核心用户故事

- 作为学习者，我可以输入一个概念，以便快速开始一次理解测试。
- 作为学习者，我可以看到一个开放式费曼问题，而不是选择题。
- 作为学习者，我可以提交自己的解释，并知道我是否理解了核心机制。
- 作为学习者，我可以区分“错误”“缺失”“证据不足”和“表达问题”。
- 作为学习者，我可以看到诊断依据与置信度，并对结果反馈。
- 作为学习者，我可以查看同一概念的历史变化和下一步行动。

## 5. MVP 范围

### P0：必须完成

1. 新建学习会话：输入主题、可选背景和自评水平。
2. 问题生成：生成一个主问题，可带 2–4 个关键覆盖点。
3. 用户回答：文本输入；支持保存草稿不是 P0。
4. 结构化诊断：分数、缺失点、误区、证据、追问、置信度。
5. 报告显示：先给结论，再给依据与建议。
6. 本地保存：会话、Prompt 版本、原始输出、解析结果和时间。
7. 历史页：按概念查看记录与简单趋势。
8. 失败处理：超时、无效 JSON、空回答、模型拒答可恢复。

### P1：核心稳定后

- 同一会话进行一轮追问并重新诊断；
- 用户评价诊断“准确/部分准确/不准确”；
- 轻量知识状态与误区标签聚合；
- 导出 Markdown/JSON；
- 支持参考材料片段。

### P2：以后

- PDF/Markdown 全量解析与 RAG；
- 语音输入；
- 复杂知识关系图；
- 账户、同步、多设备；
- React/Electron 桌面产品；
- 社区、付费、课程与公共知识库。

## 6. 核心流程

```text
Home 输入概念
  ↓
系统创建 Session
  ↓
Question Generator 返回问题
  ↓
用户提交 Explanation
  ↓
Evaluator 返回 Diagnosis
  ↓
校验并保存原始/结构化结果
  ↓
Diagnosis 页面显示报告
  ↓
用户采纳建议或进入 History
```

## 7. 功能验收

### 7.1 新建会话

输入：`concept` 必填，`context`、`self_rating` 可选。概念去除首尾空格，长度 2–100 字。提交后生成唯一 `session_id`。

异常：空输入不创建会话；重复点击不会创建多个进行中的会话。

### 7.2 生成问题

输出至少包含：

```json
{
  "concept": "梯度下降",
  "question": "请不用公式背诵，解释梯度下降如何决定参数往哪个方向更新。",
  "coverage_points": ["梯度含义", "方向", "参数更新"],
  "difficulty": "introductory",
  "prompt_version": "question-v0.1"
}
```

问题不能直接泄露完整答案；不能把表达华丽当成理解目标。

### 7.3 提交回答

回答 10–5000 字。保存用户原文，不在送入模型前默默改写。过短回答允许提交，但诊断应标记证据不足。

### 7.4 诊断

必须返回：

- `correctness`、`mechanism_understanding`、`depth`：0–100；
- `mastery_level`：no_clue / fragile / developing / solid；其中 no_clue 表示完全未掌握；
- `accurate_points`、`missing_points`、`misconceptions`；
- `evidence_quotes`：仅引用用户回答中的短片段；
- `follow_up_question`；
- `next_action`；
- `confidence`：0–1；
- `limitations`。

### 7.5 报告

展示顺序：总体判断 → 理解正确处 → 关键漏洞 → 证据 → 下一步 → 置信度与限制。避免只给一个精确分数造成权威错觉。

### 7.6 历史

显示日期、概念、掌握等级、置信度、关键误区和建议。趋势必须基于同一概念的可比记录；样本少于 2 次时不声称“提升/下降”。

## 8. 非功能要求

- 本地启动不超过 3 个命令；提供 `.env.example`。
- LLM Key 不进入代码、数据库、日志或版本库。
- 每个模型调用设置超时和有限重试。
- 数据库迁移或初始化可重复执行。
- Prompt、模型与 Schema 版本随记录保存。
- 核心业务逻辑与 Streamlit UI 解耦，可单元测试。
- 默认使用中文，但领域模型不依赖特定语言。

## 9. 指标

### 核心质量指标

- 人工诊断一致度：人工是否认可关键缺失/误区；
- 漏洞发现价值：用户是否发现自己原先未意识到的问题；
- 建议采纳率：是否执行了下一步动作；
- 校准：低置信度案例是否确实更易出错。

### 使用指标

- 完整会话率；
- 7 日内第二次使用率；
- 同概念复测率；
- 30 天个人实验完成度。

## 10. 发布门槛

原型可交付需满足：

- 20 个固定案例可批量运行；
- 强、弱、误解答案有合理区分；
- 结构化输出解析成功率达到约定阈值（目标 ≥95%）；
- 模型失败不会丢失用户回答；
- 至少完成 10 次真实个人会话；
- 所有 P0 用户故事通过验收。
