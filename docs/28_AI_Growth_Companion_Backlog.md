# AI Growth Companion v0.1 Backlog

## 1. 优先级规则

- **P0**：没有它，核心诊断闭环不能真实使用或不安全；
- **P1**：核心稳定后明显提高长期价值；
- **P2**：未来候选，当前不承诺；
- **Rejected/Paused**：目前不符合产品宪章或证据不足。

## 2. P0：MVP 必须

| ID | 功能 | 用户价值 | 验收摘要 |
|---|---|---|---|
| P0-01 | 概念输入与会话 | 快速开始 | 校验、唯一会话、可恢复 |
| P0-02 | 费曼问题生成 | 测试机制理解 | 问题不泄露答案、带覆盖点 |
| P0-03 | 用户回答 | 主动表达 | 保存原文、失败不丢失 |
| P0-04 | 结构化诊断 | 发现漏洞 | 正确/缺失/误区/证据/置信度 |
| P0-05 | Diagnosis 报告 | 理解结果 | 清晰顺序、一个下一步 |
| P0-06 | SQLite 持久化 | 形成记录 | 重启可读取、版本完整 |
| P0-07 | History | 看见历史 | 按概念/时间查询 |
| P0-08 | 可靠性 | 可真实使用 | 超时、无效 JSON、重试 |
| P0-09 | 固定测试集 | 防止回归 | 20+ 案例、人工量表 |
| P0-10 | 安全与配置 | 保护用户 | Key 不泄露、内容不越权 |

## 3. P1：验证后增强

| ID | 功能 | 进入条件 |
|---|---|---|
| P1-01 | 一轮追问 | 初次回答经常证据不足 |
| P1-02 | 诊断反馈 | 需要收集准确性数据 |
| P1-03 | 知识状态 | 同概念有重复测试 |
| P1-04 | 误区追踪 | 误区分类可靠 |
| P1-05 | 简单趋势 | 至少两次可比证据 |
| P1-06 | Markdown/JSON 导出 | 用户开始长期使用 |
| P1-07 | 周/月报告 | 有足够长期数据 |
| P1-08 | PDF/Markdown 参考 | 无材料导致事实误判成为主因 |
| P1-09 | 数据管理页面 | 进入外部用户测试前 |

## 7. 排序问题

每个候选功能评分前先回答：

1. 是否帮助用户真正掌握知识？
2. 是否产生长期可解释的认知数据？
3. 是否强化“表达 → 诊断 → 更新 → 行动”？
4. 是否解决已观察到的失败，而非想象中的未来？
5. 实现与维护成本是否与当前阶段匹配？
6. 隐私、误判和依赖风险是否可控？

若缺少实验依据，先设计低成本实验，不直接开发完整功能。
