# AI Growth Companion MVP 主 PRD

> 状态：开发基线（Baseline）  
> 版本：v0.1  
> 文档所有者：Founder / Product Owner  
> 变更规则：MVP 范围变化必须同步更新本文件、Backlog 与 ADR。

## 1. 产品定义

AI Growth Companion 是一个以费曼学习法为核心的个人学习诊断工具。它通过“提出问题—用户解释—AI 诊断—保存证据—更新认知状态—建议下一步”的闭环，帮助用户发现自己以为理解、实际尚未理解的部分，并逐步形成可查看、可纠正的个人认知模型。

长期愿景是从学习场景出发，逐步成为帮助用户学习、成长和创造的个人 AI 伙伴；但 v0.1 只验证学习诊断与认知模型的最小闭环，不假装已经具备完整成长伙伴能力。

MVP 要验证的唯一核心假设是：

> AI 能否基于用户一次及多次自然语言解释，给出有证据、可复核、不过度推断的理解诊断，并形成越来越准确、可被用户纠正的初步认知状态，从而改善下一步学习。

## 2. 目标用户与核心场景

第一位测试用户是创始人本人；第二批为 5–20 名愿意主动学习、能持续使用 2–4 周的大学生或自学者，优先覆盖数学、编程、AI 和经济学。

核心使用场景：用户完成一段学习后，输入主题并用自己的话解释；系统追问关键点，判断概念理解、推理链、应用能力和不确定性，保存本次学习记录，并给出一个最小可执行的下一步。

## 3. MVP 核心流程

1. 用户输入学习主题，可选填写目标和参考材料摘要。
2. 系统生成 1–3 个费曼问题。
3. 用户提交解释。
4. 系统按固定结构输出诊断：掌握证据、缺口、可能误解、置信度、建议。
5. 用户可确认或纠正诊断。
6. 系统保存会话、模型/Prompt 版本和反馈，并基于证据更新该知识点的暂定认知状态。
7. 历史页显示记录、证据和最小变化趋势，不做人格结论。

## 4. 功能范围

### P0：必须完成

- 新建费曼学习会话。
- 生成诊断问题并接收回答。
- 结构化诊断，输出必须通过 Schema 校验。
- 保存主题、问题、回答、诊断、时间、版本与反馈。
- 查看历史会话。
- 查看同一知识点的最小成长变化：历次诊断、证据、置信度与用户纠错状态。
- 对诊断标记“准确 / 不准确”并可填写原因。
- 失败时给出可恢复提示；不得静默丢失回答。
- 基础隐私能力：导出、删除、最少收集和敏感日志脱敏。

### P1：验证 P0 后再做

- 跨知识点的成长趋势与可解释的错误模式聚合。
- 简单月度成长报告。
- 用户上传的短文本作为会话上下文。

### 明确不做

- 多 Agent 编排、完整知识图谱、社交与商业化。
- 医疗、心理、职业或人格诊断。
- 在 MVP 阶段保存原始 PDF、音视频或大规模外部知识库。
- 自动替用户制定不可编辑的长期人生计划。
- React、Electron、移动端或复杂多租户架构。

## 5. 诊断输出契约

每次诊断至少包含：

```json
{
  "understanding_level": "novice|developing|proficient",
  "score": 0,
  "evidence": [{"claim": "", "answer_excerpt": ""}],
  "gaps": [{"description": "", "severity": "low|medium|high"}],
  "possible_misconceptions": [{"description": "", "confidence": 0.0}],
  "next_action": {"type": "review|example|practice|re_explain", "instruction": ""},
  "overall_confidence": 0.0,
  "limitations": [""]
}
```

要求：分数范围 0–100；证据必须来自本次回答；低置信度时明确表达不确定性；不得将单次表现概括成稳定人格特征。表达流畅度不是理解程度：表达简短、语言不熟练或措辞不漂亮，不能单独成为降低理解判断的依据。

## 6. 成功指标与停止条件

### 产品指标

- ≥80% 的完成会话产生可解析诊断。
- ≥70% 的测试用户认为诊断指出了具体且有用的缺口。
- ≥60% 的用户完成至少 3 次会话。
- 用户纠错后，原结论可被标记并在后续展示中降权或撤回。
- 对同一知识点进行多次测试时，系统能展示结论变化及其新增证据，而非只给出互不关联的分数。

### AI 质量门槛

- 核心测试集 Schema 通过率 100%。
- 关键事实性错误率 ≤5%。
- 无证据人格推断率为 0。
- 同一输入重复运行时，核心结论不能出现方向相反且无解释的变化。

### 停止或转向条件

若 5–20 名目标用户完成测试后，诊断帮助率持续低于 40%，或人工专家一致认为核心判断不可校准，应停止扩功能，优先修改评价任务、证据标准或产品假设。

## 7. 验收标准

一个 P0 版本只有同时满足以下条件才可称为 MVP：

- 新用户可在 5 分钟内完成一次闭环。
- 网络或模型失败后可以重试，用户回答仍在。
- 所有写入操作有稳定 ID，重复请求不会生成重复记录。
- 数据库从空库可一键迁移到当前版本。
- 自动测试、AI 回归集、隐私检查和回滚演练通过。
- README 中的全新环境启动步骤由另一人验证成功。
