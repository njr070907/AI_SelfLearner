# 可观测性、SLO 与事件响应

## 1. 目标

可观测性用于回答：系统是否可用、用户卡在哪里、模型行为是否异常、数据是否安全。默认不收集用户正文。

## 2. 事件结构

每个请求生成 `request_id`，贯穿 UI、领域服务、Provider 和数据库。结构化日志字段：时间、环境、版本、事件名、请求/会话 ID（不可直接识别用户）、结果、错误类型、延迟、模型版本和用量。

禁止记录 API Key、认证令牌、完整回答、完整 Prompt、导出内容和数据库连接串。调试正文必须显式、临时、限定本地环境，并在结束后删除。

## 3. 核心指标

- 产品：会话启动、问题生成、回答提交、诊断完成、反馈、放弃点。
- 可靠性：请求成功率、端到端完成率、P50/P95 延迟、数据库错误。
- AI：Schema 失败、修复率、拒答、用户否定、版本分布。
- 成本：请求数、输入/输出 token、单会话估算成本。
- 隐私：导出/删除成功、保留任务失败、异常管理访问。

指标标签不得包含用户正文、主题全文或高基数字段。

## 4. MVP SLO

以 30 天窗口衡量：

- 本地/小规模托管核心流程可用性 ≥99%。
- 诊断技术成功率 ≥98%（不含用户主动取消与合规拒答）。
- P95 诊断响应 ≤30 秒。
- 数据写入确认后丢失率为 0。
- 导出和删除任务成功率 100%。

达到 50% 错误预算时冻结非可靠性发布；耗尽时只允许修复、回滚和安全变更。

## 5. 告警

告警必须可行动并关联 Runbook。建议：5 分钟核心失败率 >10%、连续 Schema 失败、数据库不可写、备份失败、删除任务失败、成本突增、异常权限访问。单个偶发模型错误记录但不立即叫醒人员。

## 6. 事件等级

- SEV-0：确认的数据泄露或不可恢复损坏。立即响应、停止风险路径。
- SEV-1：大面积不可用、删除失效、系统性危险诊断。15 分钟内响应。
- SEV-2：部分用户受影响或性能严重下降。工作时间内响应。
- SEV-3：低影响异常。进入 Backlog。

## 7. 响应流程

发现 → 分级 → 指定 Incident Commander → 控制影响 → 保存证据 → 修复/回滚 → 验证恢复 → 用户/监管通知评估 → 复盘。

复盘不追责个人，必须包含时间线、用户影响、根因、为何未更早发现、恢复效果、带所有者和截止日期的行动项。
