# 发布、CI/CD 与回滚

## 1. 版本策略

应用使用语义化版本；Prompt/Schema/数据库迁移使用独立版本并汇总为 `ai_release_id`。每次发布生成不可变制品、依赖清单和变更记录。

## 2. CI 阶段

1. 依赖安装与锁文件一致性。
2. 格式、lint、类型检查。
3. 单元、集成、契约与关键 E2E。
4. 密钥、依赖漏洞和许可证检查。
5. 从空库迁移、从上一个稳定版本升级。
6. 若模型相关文件变化，运行 AI 黄金集并生成差异报告。
7. 构建不可变候选制品。

任何必须步骤失败都不可通过手工标绿绕过；紧急豁免须记录批准、风险和补偿措施。

## 3. CD 阶段

开发早期采用人工批准部署：先 Staging，完成迁移、冒烟、回滚演练，再部署 Production。部署后观察至少一个完整核心流程窗口。

推荐顺序：备份 → 兼容性迁移 → 应用 → 健康检查 → 合成会话 → 指标观察 → 宣布完成。破坏性收缩迁移放在确认旧版本不再运行之后。

## 4. 发布清单

- 范围与版本已冻结。
- 用户可见变化和已知限制已记录。
- 隐私/模型/数据影响已审查。
- 迁移、备份、恢复、回滚已验证。
- 值守人员知道版本、仪表盘和触发条件。
- 没有 S0/S1 缺陷或未处理高危漏洞。

## 5. 回滚触发器

核心失败率超过阈值、数据校验失败、越界诊断、隐私控制失败、延迟/成本严重超限、关键依赖行为异常时立即回滚或关闭功能。

应用和 Prompt 可回滚到最近验证版本。数据库优先前向修复；只有已演练且不会丢失新数据时才做结构回退。回滚不删除事件证据，也不覆盖历史诊断。

## 6. 功能开关

高风险新能力用默认关闭的开关隔离。开关有所有者、过期日期和移除任务；不得用开关长期维持两套不可测试逻辑。

## 7. 变更日志模板

```text
版本 / 日期 / 负责人
新增 / 修复 / 行为变化
模型、Prompt、Schema、迁移版本
隐私与数据影响
已知限制
验证结果
回滚版本与触发器
```
