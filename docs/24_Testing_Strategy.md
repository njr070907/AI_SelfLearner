# Testing Strategy

## 1. 目标

测试同时保护普通软件行为和 AI 产品行为。重点防止数据丢失、错误状态、不可恢复模型失败、错误画像和 Prompt 回归。

## 2. 测试金字塔

### 单元测试

- Pydantic Schema 与边界；
- 掌握等级/状态更新规则；
- 输入规范化；
- 错误映射；
- 推荐规则；
- Prompt 渲染与内容边界。

### 集成测试

- Repository + 临时 SQLite；
- 会话状态机；
- 回答先保存、诊断后更新；
- Fake LLM 成功、超时、无效 JSON；
- 级联删除与状态重算。

### 端到端测试

- Home → Session → Diagnosis → History；
- 错误后重试；
- 应用重启后恢复；
- 空状态、样本不足和诊断反馈。

### AI Eval

- 固定案例批量运行；
- 人工量表；
- Prompt A/B；
- 安全和注入案例；
- 成本/延迟记录。

## 3. Fake LLM

测试默认使用确定性 Fake：

```python
class FakeLLMClient:
    def __init__(self, responses): ...
    def generate_structured(self, ...): ...
```

可配置返回成功、超时、限流、缺字段、越界值、非 JSON 和重复响应。真实 API 测试必须显式标记并默认跳过。

## 4. 关键不变量

- 用户回答一旦提交就不会因模型失败丢失；
- 失败诊断不更新知识状态；
- 缺失点不自动记录为误区；
- 样本少于 2 次不显示趋势；
- Prompt、模型、Schema 版本随诊断保存；
- 删除用户同时删除派生状态；
- API Key 不出现在日志、异常和快照。

## 5. 必测失败路径

- 配置缺失；
- 网络中断；
- 模型超时和限流；
- 结构化输出无效；
- 数据库锁定/写入失败；
- 用户重复点击；
- 回答超长、空白、Emoji、多语言；
- Prompt 注入文本；
- UI 刷新导致状态丢失。

## 6. AI 回归集

至少覆盖：

- 4 个领域；
- 每领域多个概念；
- 强答案、弱答案、误区、空/偏题、非标准正确答案；
- 短而正确、长而空泛；
- 有/无参考材料；
- 注入和敏感推断案例。

每个版本保存汇总，不提交真实用户个人数据。

## 7. 人工验收

发布前实际完成三次会话：

1. 一个熟悉概念，故意给强答案；
2. 一个熟悉概念，故意加入误区；
3. 一个不熟悉概念，真实回答。

检查诊断证据、置信度、下一步、历史和失败恢复。

## 8. 性能与成本

记录模型调用数量、平均/P95 延迟、输入输出 token、每会话估算成本。MVP 不要求高并发，但不能一个页面触发多次无意模型调用。

## 9. 测试数据安全

- 测试 fixture 使用虚构内容；
- 真实学习记录不进入公开仓库；
- 快照和失败日志脱敏；
- 临时数据库在测试后清理；
- 不在 CI 注入不必要的生产 Key。

## 10. 完成定义

每个 P0 功能至少有成功路径、一个关键失败路径和一次手工验证。修复 Bug 先添加能复现问题的测试，再修改实现。
