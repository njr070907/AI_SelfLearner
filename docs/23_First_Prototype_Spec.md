# First Prototype Spec

## 1. 原型名称

**Feynman Intelligence Engine v0.1**

## 2. 唯一目标

验证 AI 是否能通过用户解释，发现用户自己未意识到的理解漏洞。

## 3. 演示场景

用户正在学“梯度下降”。用户输入概念后，系统提出一个机制问题。用户回答：“梯度下降就是让误差不断降低。”系统指出：目标基本正确，但没有解释梯度方向、参数更新与学习率，并给出一个追问和一个学习动作。

## 4. 最小用户流程

```text
1. 输入概念
2. 点击生成问题
3. 阅读问题
4. 输入不少于一句的解释
5. 提交
6. 查看诊断
7. 在历史中重新打开
```

## 5. 输入

- `concept`：必填，2–100 字；
- `learning_goal`：可选，最多 300 字；
- `learner_level`：可选枚举；
- `answer_text`：必填，10–5000 字。

第一版不要求上传资料，不要求注册。

## 6. 输出

- 一句总结；
- 掌握等级；
- 正确性、核心机制与深度分项；
- 已正确内容；
- 缺失内容；
- 明确误区（若有）；
- 用户回答证据；
- 一个追问；
- 一个下一步动作；
- 置信度与限制。

## 7. 文件职责

```text
app.py                         Streamlit 入口与路由
src/ui/*                      页面渲染与输入
src/application/*             会话用例编排
src/agents/question_generator 问题生成
src/agents/evaluator          结构化诊断
src/domain/models             领域对象
src/domain/schemas            AI 输出 Schema
src/infrastructure/llm_client 模型供应商适配
src/infrastructure/database   连接与初始化
src/infrastructure/repository 持久化
```

## 8. 数据

至少保存：会话 ID、概念、问题、回答、诊断、Prompt 版本、模型、Schema 版本、时间和状态。模型失败时保存回答与错误。

## 9. 技术

- Python + Streamlit；
- SQLite；
- 一个 LLM 供应商适配器；
- Pydantic；
- pytest；
- `.env` 配置。

## 10. 非目标

- 登录、多用户、同步；
- PDF、RAG、知识图谱；
- 多 Agent 自主编排；
- 语音、白板和视频；
- 复杂 Dashboard；
- 社区、商业化和桌面打包；
- 长期人格画像。

## 11. 成功标准

### 技术

- 干净环境可启动；
- 完整流程成功；
- 无效模型输出可恢复；
- 应用重启后记录仍存在；
- 测试默认不调用真实 API。

### AI

- 至少 20 个固定案例；
- 强、弱和误区答案有合理区分；
- 关键结论带原文证据；
- 短但正确的回答不因文风被低估；
- 没有证据时降低置信度。

### 产品

- 产品负责人完成 10 次真实使用；
- 至少 3 次诊断发现真实未知漏洞；
- 用户能在不解释的情况下理解报告；
- 至少一次建议被执行并复测。

## 12. 停止条件

如果多轮 Prompt 与参考材料改进后，人工仍无法稳定认可诊断，暂缓扩展，重新审视核心假设；不得以新增 UI 或更多 Agent 掩盖诊断质量问题。
