# UI / UX 规范

## 1. 体验目标

用户应在 10 分钟内完成一次“输入概念 → 回答 → 诊断 → 决定下一步”的闭环。界面服务于专注思考，不使用过度游戏化或信息密集仪表盘。

## 2. 信息架构

### Streamlit 原型

1. **Home**：开始新测试、查看最近成长；
2. **Feynman Session**：显示问题并输入回答；
3. **Diagnosis**：显示诊断与下一步；
4. **History**：查看概念记录和趋势。

### 未来产品

- Dashboard / My Growth
- Learning Map
- Learning Room
- Feynman Lab
- Cognitive Profile
- Settings & Data

## 3. Home

优先顺序：

1. 主标题：“今天想检验哪个知识点？”
2. 概念输入框；
3. 可选学习目标与自评；
4. “开始费曼挑战”主按钮；
5. 最近 3 次会话；
6. 有足够数据时展示一条成长变化。

空状态说明：用户不需先上传材料或建立完整档案即可开始。

## 4. Feynman Session

页面包含：

- 概念与问题；
- 提醒：“请不用查资料，用自己的话解释。表达不漂亮没有关系。”
- 大文本输入区；
- 字数仅作提示，不作为质量指标；
- “提交诊断”按钮；
- 提交中状态和取消/恢复说明。

不要在回答前显示覆盖点、参考答案或评分维度细节，以免诱导背诵。

## 5. Diagnosis

### 展示顺序

1. **一句话判断**：例如“你理解了目标，但参数更新机制仍不清楚”。
2. **掌握等级**：使用文字标签，不只用百分比。
3. **你已经说对的**：先肯定具体证据。
4. **最关键的漏洞**：最多 3 条，区分遗漏与误区。
5. **依据**：短引用用户回答。
6. **下一步行动**：一个主要建议。
7. **追问**：可选继续一次。
8. **置信度与限制**。
9. **结果反馈**：准确 / 部分准确 / 不准确。

### 文案规则

- 使用“目前回答显示……”而非“你就是……”；
- 不把 73% 等精确分数作为最大视觉元素；
- 误区说明包含“你表达了什么”和“为什么不准确”；
- 不因低分使用羞辱、警告或失败动画。

## 6. History

列表项显示：日期、概念、掌握等级、关键漏洞、置信度。点击进入完整会话。

同概念有 2 次以上可比记录时显示时间线；否则显示“继续复测后可看到变化”，不生成虚假趋势。

## 7. Cognitive Profile（P1）

每条 AI 理解卡片包含：

- 观察结论；
- 证据数量与时间范围；
- 支持证据和反证；
- 置信度；
- 用户反馈；
- 查看、纠正、隐藏和删除入口。

候选模式与较强模式在视觉上明确区分。

## 8. 状态设计

必须覆盖：

- 空状态；
- 加载中；
- 成功；
- 输入校验失败；
- 模型超时/限流；
- 结果格式无效；
- 数据库失败；
- 无网络；
- 重试后成功。

错误消息需告诉用户：发生了什么、数据是否保存、现在能做什么。

示例：

> 诊断服务暂时未返回有效结果。你的回答已经保存，可以直接重试，无需重新输入。

## 9. 可访问性

- 不只用颜色表达掌握状态；
- 主要操作可用键盘完成；
- 文本对比度符合常规可读标准；
- 输入区和按钮有清晰标签；
- 动画可减少；
- 中文正文建议 16px 等效以上，行距舒适。

## 10. 视觉方向

清晰、克制、可信，接近研究工具与个人学习空间，而不是热闹课程商城。使用单一主色、有限状态色、充足留白和明确层级。图表只在展示真实变化时出现。

## 11. 原型验收任务

让第一次使用者独立完成：

1. 输入“梯度下降”；
2. 找到并理解问题；
3. 提交解释；
4. 说出 AI 认为的一个正确点和一个漏洞；
5. 找到下一步建议；
6. 在历史中重新打开记录。

若用户需要开发者解释界面，视为失败。
