# 测试与质量策略

## 1. 测试目标

测试不仅证明“代码能跑”，还要证明：诊断输出可解析、结论有证据、失败可恢复、隐私权可执行、模型升级不会悄悄改变产品行为。

## 2. 测试分层

| 层级 | 内容 | 每次提交 |
|---|---|---|
| 单元 | 领域规则、Schema、评分、脱敏、幂等 | 是 |
| 集成 | SQLite、迁移、Provider 适配、事务 | 是 |
| 契约 | 诊断 JSON、版本字段、错误类型 | 是 |
| 端到端 | 新建会话到反馈、导出、删除 | 主分支/发布 |
| AI 评估 | 黄金样例、对抗输入、一致性、校准 | Prompt/模型变更 |
| 非功能 | 性能、可靠性、安全、可访问性 | 发布前 |

## 3. 必测场景

- 正常流程：主题—问题—回答—诊断—历史—反馈。
- 空白、超长、多语言、含代码和格式破坏字符的输入。
- Prompt 注入：用户回答中要求泄露系统提示或忽略评价标准。
- 模型超时、限流、拒绝、无效 JSON、缺字段、重复响应。
- 用户双击提交、刷新、进程重启和数据库暂时不可用。
- 导出完整性、删除不可见性、保留期清理、日志脱敏。
- 旧数据库升级、失败迁移恢复和备份恢复。

## 4. AI 黄金集

在现有 `29_Feynman_Agent_Test_Cases.md` 基础上，每条样例保存：领域、题目、用户回答、专家期望、允许差异、禁止结论、严重度与数据版本。

至少包含：

- 正确但表达简短。
- 理解正确但语言不流畅、存在语法问题或使用非标准术语。
- 流畅但核心概念错误。
- 部分正确且明确表达不确定。
- 正确结论但推理错误。
- 与主题无关、复制材料、拒绝回答。
- 边界领域与无法可靠判断的回答。

## 5. AI 评分维度

- 正确性：诊断本身是否符合领域事实。
- 证据性：每个判断能否定位到回答证据。
- 覆盖度：关键缺口是否被发现。
- 校准：置信度是否匹配证据强度。
- 可行动性：下一步是否具体且最小。
- 安全性：是否避免人格化、歧视性或越界判断。
- 表达独立性：是否把语言流畅、篇幅或术语熟练错误地当成理解程度。
- 纵向一致性：多次回答之间的认知状态变化是否由新增证据支持，并正确处理用户纠错。

自动评审只能做初筛；发布门槛以固定规则和人工抽样为准。不得仅使用同一模型自评后直接发布。

## 6. 发布门槛

- 代码检查与确定性测试 100% 通过。
- P0 端到端场景 100% 通过。
- 关键/高危安全问题为 0。
- 黄金集相对基线无严重回归；总体分不得下降超过预设容差。
- Schema 通过率 100%，无证据人格判断为 0。
- “仅因表达不流畅而低估理解”的关键样例回归数为 0。
- 备份恢复和回滚路径在候选版本上演练成功。

## 7. 缺陷严重度

- S0：泄露/删除错误/不可恢复数据损坏。立即停服或禁用相关能力。
- S1：核心诊断大面积错误、无法完成闭环。阻断发布。
- S2：部分场景错误但有替代路径。下一补丁修复。
- S3：低影响显示或文案问题。进入 Backlog。

## 8. 测试数据

测试默认使用合成数据。真实用户样本必须去标识化、取得对应授权、限制访问并设删除日期。生产数据不得复制到开发环境。
