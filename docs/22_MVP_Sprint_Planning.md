# MVP Sprint Planning

## 1. 节奏

建议 1 周一个 Sprint，每天 1–2 小时。每个 Sprint 交付可运行的垂直结果，并以真实使用结束。

## Sprint 0：环境与仓库

### 目标

任何新环境都能启动空应用并运行测试。

### 工作

- 建立目录、`pyproject.toml`、`.env.example`；
- Streamlit 空页面；
- SQLite 初始化；
- pytest 与 Fake LLM；
- 日志与配置校验；
- README 快速启动。

### 验收

干净环境按文档启动；一个示例测试通过；没有真实 Key 或数据库被提交。

## Sprint 1：Feynman Agent Prototype

### 目标

固定假数据贯通概念输入、问题、回答和诊断报告。

### 工作

- Question、Explanation、Diagnosis 领域模型；
- Home、Session、Diagnosis 页面；
- 固定 Question Generator / Evaluator；
- UI 状态管理；
- 基础输入校验。

### 验收

不调用模型也能完成完整用户流程，界面能解释正确点、漏洞和下一步。

## Sprint 2：真实 AI 与可靠性

### 目标

接入真实 LLM，并让输出稳定、可恢复。

### 工作

- LLM Gateway；
- Question/Evaluator Prompt v0.1；
- Pydantic Schema；
- 超时、重试、格式修复；
- 模型元数据记录；
- 固定评估集运行器。

### 验收

20 个案例可批量评估；无效输出不会生成正式诊断；用户看到可重试状态。

## Sprint 3：数据保存与历史

### 目标

所有会话可恢复、查看和比较。

### 工作

- 数据库表与 Repository；
- 回答先保存 pending；
- 事务与状态机；
- History 页面；
- 集成测试与级联删除测试。

### 验收

模型调用失败后回答仍存在；应用重启后历史可查看；重复点击不产生错误重复数据。

## Sprint 4：Cognitive Profile 基础

### 目标

同一概念的多次记录形成保守的知识状态。

### 工作

- knowledge_states；
- 误区与缺失点分离；
- 简单趋势；
- 诊断反馈；
- 状态重算脚本。

### 验收

样本不足时不显示趋势；错误诊断可因用户反馈降低权重；状态可从历史重算。

## Sprint 5：材料输入实验（条件性）

只有评估显示“缺少参考知识”是主要错误来源才进入。

### 工作

- 单份 PDF/Markdown；
- 解析、chunk、来源；
- 轻量检索；
- 有/无材料 A/B 评估。

### 验收

材料显著改善事实诊断，来源可追溯，注入测试通过。

## Sprint 6：30 天真实测试

### 目标

停止新增功能，验证每日价值。

### 工作

- 按协议使用；
- 记录诊断准确性、建议采纳和失败；
- 每周复盘 Prompt 与交互；
- 只修复阻塞和严重错误。

### 验收

完成个人实验报告，明确继续、调整或停止哪些方向。

## 8. Sprint 规则

- 一个 Sprint 只有一个核心问题；
- 未完成 P0 不开始 P1；
- 技术债必须关联实际风险；
- 每周至少一次真实用户流程；
- 结束时更新实验日志和 Backlog；
- 未验证的新增想法只记录，不立刻开发。
