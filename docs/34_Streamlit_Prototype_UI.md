# Streamlit Prototype UI

## 1. 目标

用 Streamlit 最快验证核心学习体验。原型优先清晰、可信、可测试，不追求最终视觉品牌。

## 2. 页面/状态

Streamlit 可使用多页面，也可用单入口状态机。逻辑上包含：Home、Feynman Session、Diagnosis、History。

## 3. Home

### 元素

```text
AI Growth Companion
检验自己是否真正理解

[知识点输入________________]
[学习目标（可选）__________]
[当前水平（可选）▼]
[开始费曼挑战]

最近学习
- 梯度下降  Developing  2小时前
```

### 行为

- 知识点为空时不提交；
- 提交后创建会话并进入问题页；
- 配置缺失时顶部显示明确设置说明；
- 无历史时显示一个示例概念，但不自动创建数据。

## 4. Feynman Session

```text
概念：梯度下降

请向没学过机器学习的人解释：
梯度下降如何决定参数往哪个方向更新？

提示：请不用查资料，用自己的话解释。
表达不漂亮没有关系，重点是你的理解。

[多行回答输入框____________________]
[___________________________________]

[提交诊断]  [返回]
```

提交前保存本地输入状态；提交时显示“正在分析你的解释”，禁用重复点击。不要显示覆盖点。

## 5. Diagnosis

```text
总体判断：理解了目标，但核心更新机制仍不清楚
[掌握发展中]  证据置信度：中等

你已经说对的
✓ 知道目标是降低误差

最关键的漏洞
1. 没有说明梯度如何决定方向
2. 没有说明学习率如何控制步长

依据
“不断让误差变小”支持你理解优化目标……

下一步（约20分钟）
用一维函数图解释梯度、负方向和学习率，再重新回答。

[回答追问] [回到首页] [查看历史]

这个诊断准确吗？ [准确] [部分准确] [不准确]

为什么不确定？
回答较短，尚无法判断应用能力。
```

分数可放在可展开详情，不作为首屏最大内容。

## 6. History

### 筛选

- 概念搜索；
- 状态；
- 日期。

### 列表

| 时间 | 概念 | 掌握 | 关键问题 | 置信度 |
|---|---|---|---|---|

点击行/按钮打开完整记录。同概念少于 2 次时不画趋势；2 次以上显示简洁时间线与“证据有限”说明。

## 7. 侧边栏

- 新测试；
- 历史；
- 开发模式开关（仅本地）；
- 数据位置与隐私简述；
- 版本。

开发模式可显示 Prompt、模型和 Schema 版本，不默认显示原始模型输出。

## 8. Session State

建议字段：

```text
current_session_id
current_question_id
draft_answer
navigation_state
last_error
```

数据库是事实源，session state 只保存临时 UI 状态。刷新后通过 `current_session_id` 恢复。

## 9. 错误状态

### 模型超时

> 诊断服务响应超时。你的回答已保存，可以直接重试。

按钮：`重试诊断`、`稍后在历史中继续`。

### 输出无效

> 模型返回的结果未通过格式检查，因此没有写入正式诊断。回答已保存。

### 配置缺失

> 尚未配置模型服务。你可以使用演示模式，或按本地设置说明添加 API Key。

### 数据库错误

不要承诺数据已保存；显示错误 id 和安全的恢复建议。

## 10. 视觉与文案

- 最大宽度适合长文本阅读；
- 主色一套，状态色不只依赖颜色；
- 充足留白，避免同时展示所有指标；
- 用“掌握尚脆弱/发展中/较稳固”而非“失败”；
- 不使用连续打卡压力、排行榜和夸张庆祝。

## 11. 可测试性

UI 调用 Service，使用返回的 View Model。关键组件使用稳定 label/key，便于 Streamlit 测试。Fake LLM 模式下 E2E 结果确定。

## 12. 迁移路线

```text
Streamlit Prototype
        ↓ 核心交互验证
React Web / Electron UI
        ↓
FastAPI Application Boundary
```

迁移时保留 Domain、Application、LLM Gateway 和 Repository，不复制 Streamlit 状态逻辑。
