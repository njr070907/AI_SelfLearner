# 部署与运维 Runbook

## 1. 环境

- Local：个人开发，Fake Provider 默认可用。
- Test/CI：临时数据库与合成数据。
- Staging：与生产配置同构，用于迁移、模型和发布验证。
- Production：最小权限、禁用调试、启用备份与告警。

MVP 可先本地部署；启用外部用户前必须补齐认证、TLS、生产数据库访问控制和隐私告知。

## 2. 部署前检查

1. 候选版本已打不可变标签并生成变更记录。
2. CI 与 AI 评估通过。
3. 数据迁移已在生产备份副本演练。
4. 已确认配置、密钥和模型版本。
5. 已创建备份并验证可读。
6. 指定发布负责人、观察窗口与回滚触发器。

## 3. 启动与健康

健康检查至少区分：

- Liveness：进程是否存活，不调用外部模型。
- Readiness：数据库版本、必要配置和写入能力是否正常。
- Dependency status：模型供应商状态单独展示，不让其拖垮 liveness。

## 4. 备份与恢复

- SQLite 本地版：关闭写入或使用一致性快照后备份数据库文件。
- 生产版：每日自动备份，保留策略见 46；重要迁移前额外备份。
- 每月至少一次恢复演练，记录 RTO/RPO 实测值。
- 备份加密，访问与生产数据库分离。

目标：MVP RPO ≤24 小时，RTO ≤4 小时。进入付费或多人生产前重新评估。

## 5. 常见故障处理

### 模型错误率升高

暂停模型/Prompt 发布；检查供应商状态、错误类别和配额；必要时切回已评估版本。不得自动切换到未验证模型。

### 数据库不可写

进入只读或维护模式；阻止新诊断写入；保留用户本地草稿；检查磁盘、锁和迁移版本；恢复后验证事务一致性。

### 诊断质量异常

冻结相关版本；保存脱敏请求 ID；抽样复核；回滚 Prompt/模型；对已受影响诊断加版本警示，必要时重新计算但不覆盖原始记录。

### 疑似数据泄露

立即撤销相关凭据、限制访问并保留取证信息；按 47 的事件流程分级；评估受影响数据和用户通知义务。

## 6. 维护任务

- 每日：错误率、延迟、成本、备份状态。
- 每周：AI 反馈异常、未处理告警、依赖漏洞。
- 每月：恢复演练、权限复核、保留期清理、模型漂移抽样。
- 每季度：灾难恢复、威胁模型、文档与联系方式复核。

## 7. 关停

关停前提供数据导出窗口；停止新写入；完成最终备份；执行用户数据删除/保留承诺；撤销密钥与服务账号；记录删除证明和未完成义务。
