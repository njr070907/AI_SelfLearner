# AI 模型治理

## 1. 治理对象

“AI 版本”由模型供应商、模型名/修订、系统 Prompt、任务 Prompt、工具、采样参数、输出 Schema、后处理代码和评估集共同组成。任一项变化都可能改变产品行为。

## 2. 版本登记

每个诊断保存：

```text
ai_release_id
provider / model / model_revision
system_prompt_version / task_prompt_version
schema_version / evaluator_version
temperature / key parameters
evaluation_dataset_version
request_id / created_at
```

不得依赖 `latest` 等漂移别名作为可追溯版本；供应商不提供精确修订时，记录可得信息和观测日期。

## 3. 变更流程

1. 提出变更假设和期望改善指标。
2. 在固定黄金集运行旧版与候选版。
3. 检查严重错误、证据性、校准、格式、延迟和成本。
4. 人工盲评关键与差异样例。
5. 记录批准者、结果、限制和回滚版本。
6. 小流量或内部观察后再扩大。

不得一边更换模型、一边大改 Prompt 和 Schema，却把结果归因于单一变化。

## 4. 输出边界

- 诊断是学习证据的解释，不是对人的定性。
- 每个重要判断都要引用用户回答或明确的历史证据。
- 证据不足时输出限制和追问，不用流畅语言掩盖不确定性。
- 不生成医疗、心理、人格、智力或职业适配结论。
- 用户反馈优先于模型派生画像；被否定的结论不得静默恢复。

## 5. 质量与风险分级

- 高风险变化：系统 Prompt、评价标准、Schema、主模型、用户画像聚合。必须完整回归、人工批准和可回滚发布。
- 中风险变化：采样参数、上下文选择、后处理。必须针对性回归。
- 低风险变化：不改变语义的文案或展示。执行确定性测试。

## 6. 监控

按 AI release 监控：Schema 失败率、拒答率、用户否定率、无证据结论率、严重事实错误抽样、重复一致性、延迟、token 和单次成本。指标变化只提示调查，不能自动证明模型“变聪明”或“变差”。

## 7. 回滚

保留至少一个已验证版本。触发条件包括：严重事实错误显著上升、越界判断、格式失败阻断核心流程、成本或延迟超限、供应商行为未告知变化。回滚后不覆盖历史诊断；以版本标记受影响记录，必要时向用户提示重新评估。

## 8. 供应商治理

上线前核对：数据用途与保留、训练默认项、数据地区、子处理方、删除能力、服务稳定性、版本通知、限流和成本。供应商条款变化应触发隐私与模型治理复审。
