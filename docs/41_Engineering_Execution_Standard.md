# 工程执行标准

## 1. 环境与依赖

- 支持当前稳定 Python 版本，具体版本锁定在 `.python-version` 与 CI。
- 使用 `pyproject.toml` 和锁文件；生产与开发依赖分组。
- 所有配置来自环境变量或配置文件；启动时验证必填项。
- `.env.example` 不得包含真实密钥、用户数据或可用凭据。
- 依赖升级由自动测试、AI 回归集和变更记录共同验证。

## 2. 代码边界

- UI 不直接执行 SQL 或厂商模型调用。
- 领域层不导入 Streamlit 或具体数据库驱动。
- 外部调用必须有超时、有限重试和错误分类。
- 时间使用 UTC 存储、ISO 8601 交换、本地时区展示。
- ID 使用 UUID；金额、token、分数等字段明确单位和范围。
- 数据写入用事务；可重试操作带幂等键。

## 3. 质量检查

提交前必须通过：格式化、lint、类型检查、单元测试、集成测试、密钥扫描和迁移检查。合并到主分支前，核心路径端到端测试与 AI 黄金集必须通过。

最低覆盖原则：不以单一覆盖率代替质量；领域规则、隐私删除、迁移和错误恢复必须分支覆盖。建议整体行覆盖率不低于 80%，核心领域不低于 90%。

## 4. Definition of Ready

任务开始前应明确：用户价值、范围/非范围、验收标准、数据影响、模型影响、失败行为和回滚方式。缺少安全或数据决策时不得进入实现。

## 5. Definition of Done

- 代码与测试完成，验收标准可复现。
- 新迁移可升级、可验证，并有恢复方案。
- 日志不含敏感正文，新增指标有名称与用途。
- 用户可见变化更新 README/变更日志。
- 模型行为变化登记版本并运行回归评估。
- 不遗留无所有者的 TODO；已知问题进入 Backlog。

## 6. 分支与评审

- 主分支始终可发布；短生命周期功能分支。
- PR 小而完整，描述风险、验证和回滚。
- 涉及认证、删除、导出、密钥、迁移、Prompt 或诊断 Schema 的变更必须人工评审。
- 禁止直接修改生产数据来“修复”应用逻辑。

## 7. 配置项基线

```text
APP_ENV
DATABASE_URL
LLM_PROVIDER
LLM_MODEL
LLM_API_KEY
LLM_TIMEOUT_SECONDS
LOG_LEVEL
LOG_CONTENT_ENABLED=false
TELEMETRY_ENABLED
DATA_RETENTION_DAYS
```

生产环境启动时若检测到调试模式、默认密钥、正文日志或未知数据库版本，应拒绝启动。
