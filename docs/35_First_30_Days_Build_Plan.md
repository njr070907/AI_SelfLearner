# First 30 Days Build Plan

## 总目标

30 天内完成一个自己每天可以使用的 Feynman Agent Prototype，并形成第一轮真实产品证据。每天建议 1–2 小时；优先完成结果，不补全所有理论。

## Week 1：最小 AI 交互

### Day 1：项目启动

- 阅读 00、02、23、33；
- 建仓库、Python 环境、README；
- 启动 Streamlit 空页面。

**验证**：干净终端可启动。

### Day 2：领域模型

- 定义 Session、Question、Explanation、Diagnosis；
- 写 Schema 边界测试。

**验证**：有效/无效样例符合预期。

### Day 3：Fake 问题生成

- Home 输入概念；
- 用固定生成器进入 Session。

**验证**：无 API Key 可走到回答页。

### Day 4：Fake 诊断

- 提交回答；
- 展示固定结构化诊断。

**验证**：完成最小端到端闭环。

### Day 5：Question Prompt

- 实现 LLM Gateway；
- 接入 question-v0.1。

**验证**：5 个概念问题不泄露答案且测试机制。

### Day 6：Evaluator Prompt

- 接入 evaluator-v0.1；
- Schema 校验。

**验证**：强/弱/误区三种回答有合理区分。

### Day 7：周复盘

- 自己完成 3 次真实测试；
- 记录 Prompt 失败和用户体验；
- 不加新功能。

## Week 2：可靠诊断流程

### Day 8：错误分类

实现配置、超时、限流、输出无效错误。

### Day 9：格式修复

只允许一次结构修复；失败返回可恢复状态。

### Day 10：证据验证

检查引用片段必须来自用户回答。

### Day 11：测试案例—数学/编程

把 29 中案例结构化为 fixture。

### Day 12：测试案例—AI/经济学

补完四领域和通用鲁棒案例。

### Day 13：人工评分

盲评当前输出，记录严重错误和改进假设。

### Day 14：Prompt v0.2 决策

只针对最高频失败修改；跑完整回归集并采用/拒绝。

## Week 3：数据保存与历史

### Day 15：SQLite Schema

建立 users、concepts、sessions、questions。

### Day 16：回答与诊断表

建立 explanations、diagnoses、版本字段。

### Day 17：Repository

实现 CRUD 与临时数据库测试。

### Day 18：回答先保存

重构诊断用例：保存 pending 后再调用模型。

### Day 19：状态机和重试

实现失败状态、合法转换和重试。

### Day 20：History

列表和完整会话查看。

### Day 21：故障演练

模拟超时、无效 JSON、数据库错误、重复点击；确认数据处理准确。

## Week 4：真实实验准备

### Day 22：诊断反馈

加入准确/部分/不准确和备注。

### Day 23：基础知识状态

同概念记录聚合；样本不足不显示趋势。

### Day 24：下一步建议

每次报告只给一个行动和完成检查。

### Day 25：UI 清理

完成 Home、Session、Diagnosis、History 的空/错/加载状态。

### Day 26：隐私与日志

检查 Key、回答、原始响应和数据库的边界；补 `.gitignore`。

### Day 27：干净环境安装

按 README 从零安装，修复所有断点。

### Day 28：真实学习日

用产品学习 3 个真实概念，不以演示答案代替。

### Day 29：产品复盘

回答：AI 是否发现真实漏洞？是否愿每天使用？最无价值和最危险的部分是什么？

### Day 30：发布 v0.1 原型

- 打 tag；
- 保存评估基线；
- 写 30 天构建总结；
- 选择“进入个人 30 天实验 / 继续修诊断 / 暂停核心假设”。

## 每日结束模板

```markdown
- 今天完成：
- 实际验证：
- 发现的失败：
- 产品判断：
- 明天唯一目标：
```

## 30 天完成标准

- 应用可在本地稳定启动；
- 核心闭环和历史可用；
- 20+ 固定案例；
- 真实失败可恢复；
- 至少 10 次真实学习会话；
- 有清晰继续/调整/停止决定。
